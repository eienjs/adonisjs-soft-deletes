Once the provider is registered and your database table has a `deleted_at` column, you can enable soft deletes on any Lucid model using the `SoftDeletes` mixin.

## Defining a Model

Use `@adonisjs/core/helpers` `compose` to apply the `SoftDeletes` mixin to your `BaseModel`:

```ts [app/models/user.ts]
import { compose } from '@adonisjs/core/helpers';
import { BaseModel, column } from '@adonisjs/lucid/orm';
import { SoftDeletes } from '@eienjs/adonisjs-soft-deletes/lucid/mixin';
import { DateTime } from 'luxon';

export default class User extends compose(BaseModel, SoftDeletes) {
  @column({ isPrimary: true })
  declare public id: number;

  @column()
  declare public email: string;

  @column.dateTime({ autoCreate: true })
  declare public createdAt: DateTime;

  @column.dateTime({ autoCreate: true, autoUpdate: true })
  declare public updatedAt: DateTime | null;
}
```

::note
The `SoftDeletes` mixin automatically defines `@column.dateTime() declare public deletedAt?: DateTime | null;`. You do not need to redeclare `deletedAt` unless you want to customize its column options.
::

### Custom `deletedAt` Column Name

If your database table uses a different column name for the deletion timestamp, override the `deletedAt` property on your model with `@column.dateTime({ columnName: '...' })`. All hooks and query macros automatically read the configured `columnName`:

```ts [app/models/post.ts]
import { compose } from '@adonisjs/core/helpers';
import { BaseModel, column } from '@adonisjs/lucid/orm';
import { SoftDeletes } from '@eienjs/adonisjs-soft-deletes/lucid/mixin';
import { DateTime } from 'luxon';

export default class Post extends compose(BaseModel, SoftDeletes) {
  @column({ isPrimary: true })
  declare public id: number;

  @column.dateTime({ columnName: 'archived_at' })
  declare public deletedAt?: DateTime | null;
}
```

## Working with Model Instances

### Soft Deleting a Model

Calling `.delete()` on a model instance sets `deletedAt` to `DateTime.local()` and persists the change via `.save()`. The model's `$isDeleted` flag remains `false` because the row still exists in the database:

```ts
const user = await User.findOrFail(1);

await user.delete();

console.log(user.$trashed); // true
console.log(user.deletedAt); // DateTime instance
console.log(user.$isDeleted); // false
```

### Checking if a Model is Trashed

Use the `.$trashed` getter to check whether a model instance is currently soft-deleted:

```ts
if (user.$trashed) {
  // Record has a non-null deletedAt timestamp
}
```

### Restoring a Soft-Deleted Model

Calling `.restore()` on a trashed model instance sets `deletedAt` back to `null` and saves the model:

```ts
const user = await User.withTrashed().where('id', 1).firstOrFail();

await user.restore();

console.log(user.$trashed); // false
console.log(user.deletedAt); // null
```

::tip
If `.restore()` is called on an active model (`user.$trashed === false`), it returns the model immediately without executing an unnecessary database update.
::

### Permanently Deleting a Model

To permanently remove the record from the database (`DELETE FROM ...`), call `.forceDelete()`:

```ts
const user = await User.findOrFail(1);

await user.forceDelete();

console.log(user.$isDeleted); // true
```

::caution
Attempting to call `.restore()` on an instance that has been permanently deleted with `.forceDelete()` throws an `E_MODEL_FORCE_DELETED` exception.
::

## Querying Models

### Default Filtering

By default, all `find`, `fetch`, and `paginate` queries on a soft-deletable model automatically apply `WHERE <table>.<deleted_at_column> IS NULL`:

```ts
// Only returns records where deleted_at IS NULL
const activeUsers = await User.all();
const user = await User.find(1);
const page = await User.query().paginate(1, 20);
```

### Including Trashed Models (`withTrashed`)

To include both active and soft-deleted records in a query, use `.withTrashed()` on the model or query builder:

::code-group
```ts [Static Helper]
const allUsers = await User.withTrashed().orderBy('id', 'asc');
```

```ts [Query Builder Macro]
const allUsers = await User.query().withTrashed().orderBy('id', 'asc');
```
::

### Querying Only Trashed Models (`onlyTrashed`)

To retrieve exclusively soft-deleted records (`WHERE <table>.<deleted_at_column> IS NOT NULL`), use `.onlyTrashed()`:

::code-group
```ts [Static Helper]
const trashedUsers = await User.onlyTrashed().orderBy('deleted_at', 'desc');
```

```ts [Query Builder Macro]
const trashedUsers = await User.query().onlyTrashed().orderBy('deleted_at', 'desc');
```
::

### Bulk Restoring via Query Builder

You can restore multiple soft-deleted records at once in a single `UPDATE` query by chaining `.restore()` on the query builder:

```ts
const affectedRows = await User.query()
  .onlyTrashed()
  .where('company_id', 5)
  .restore();
```

### Relationships and Preloading

Because `ignoreDeleted` is registered as `@beforeFind` and `@beforeFetch` hooks on the model, preloaded relationships pointing to a soft-deletable model also exclude soft-deleted rows by default. You can use `.withTrashed()` or `.onlyTrashed()` inside preload callbacks:

```ts
const companies = await Company.query().preload('users', (usersQuery) => {
  usersQuery.withTrashed();
});
```
